选题：Rustlings-Adaptive —— 对话式 Rust 诊断教练

Rust 的所有权、生命周期、泛型、trait 等概念仅靠文档难以内化，社区公认
上手最快的方式是 rustlings 这类填空练习：给一段故意写残的代码让学习者
补全，由编译器与测试当场判对错。但 rustlings 题目固定、不区分基础与
短板，也不记录学习者的错误，无法定向巩固。

另一方面，通用 LLM 能把概念解释清楚，却不解决两个问题：其一，它不会在
本地跑 rustc 验证自己给的代码，常产出含语法或类型错的片段；其二，它不
记录学习者的历史错误，无法在对话中针对刚暴露的薄弱点即时出题验证。结果
是学习者听完解释说“我懂了”，遇到稍有变化的场景仍然出错，同类错误反复
犯。根本原因在于，通用 Agent 既缺持久状态，也无法可靠地在本地执行与
校验代码。

本项目旨在做一个对话式 Rust 诊断教练 Agent。rustlings 式填空不再作为
独立题库，而是作为对话中的即时诊断工具：题目质量标准从“客观优秀”放宽
为“与当前上下文相关、能暴露薄弱点、机器可解”，从而绕开稀疏数据下题目
质量难以量化的难题。核心流程为：用户提问或贴报错 → Agent 解释并解析
其中 rustc 错误码（E0xxx）作为知识点锚点 → 据薄弱知识点选/填一道填空题
（模板化 + 参数化），本地 rustc --test 做“能编译 / 参考解全绿 / todo
模板必失败”三重校验，不通过自动重试 → 学习者在 CLI 中做题并获实时
反馈 → 通过后做“原理解释 + 多解对比”复盘（见下）→ 错误码、修复与
解释归入错误画像与错题本，据此定向巩固。

与通用 Agent 的差异主要在四点：一是将 rustc 作为 Agent 可调用工具，任何
要给用户的题必过本地三重校验，保证机器可解；二是以 rustc 错误码作为
知识点锚点（如 E0277↔trait-impl、E0499↔exclusive-mutable-borrow），
错误画像精确到错误码级，据此定向出题与检索；三是“原理解释 + 多解对比”
复盘——Agent 复现原失败代码与真实 rustc 诊断，请学习者解释为何编译失败
并据真实错误码校核其解释，再生成 2–3 种都能通过编译的不同写法，实跑
clippy 警告数、编译时长与运行时给出对比表，让学习者判断哪种更合适，把
“是否真懂”建立在真实诊断与可测量的取舍之上；四是“借用检查器假设
实验室”——学习者假设性修改代码（如增加生命周期参数），Agent 实际重跑
rustc 并返回诊断增量，使借用规则的因果可观察。四者都依赖真实本地执行，
是通用 Agent 难以做到的。

主要功能：对话 REPL 与菜单（自然语言提问、即时出题、长任务可打断）、
模型可配置（endpoint/key/价格/上下文长度，支持 OpenAI 与本地模型）、
模板化题目生成与本地三重校验、原理解释与多解对比复盘、错误码画像与
错题本（带检索）、历史会话存 JSON 可回看、每次调用的 token 用量与
价格统计及预算上限。

选题与课程本身契合：本课程即“边学 Rust 边在 AI 辅助下完成项目”，一个
在对话中即时诊断与验证、据错误定向巩固的 Agent 正是即用即学的范式。
验证器与语言解耦，未来可迁移至其他语言，但主线只做 Rust。

期待指正，尤其是模板库的初始覆盖范围与错误码到知识点的映射维护两项。
