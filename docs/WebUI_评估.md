# Web UI 可行性与成本评估（9.5，仅分析未实施）

> 结论先行：**技术上顺畅、架构上低摩擦、时间上不建议在 9.10 前投入**。
> MVP 约需 4-5 个全天，完整版 7-12 个全天；R2 已由 CLI 满足，Web 是
> 展示加分项而非硬要求。若做，推荐"Rust axum 后端 + 轻前端 + WebSocket"
> 的最小闭环（对话 + 出题 + 做题），画像/复盘等页面后补。

## 一、架构现状对 Web 的友好度（重要前提）

项目的模块划分恰好是"表现层 / 核心逻辑"分离的：

| 层 | 内容 | Web 化成本 |
|---|---|---|
| `cli/` | REPL、渲染、输入层、practice 交互循环 | **丢弃重写**（Web 不需要终端渲染与 raw-mode） |
| `agent/` | 工具环、run_turn、会话轨迹 | **直接复用**（progress 已是闭包注入，可改为事件通道） |
| `generator/` `review/` `profile/` `verifier/` | 出题/评审/画像/验证 | **直接复用**（纯 Rust，无终端依赖） |
| `llm/` | blocking reqwest | 可复用；Web 并发下建议包 tokio::task::spawn_blocking |
| `exercise/` `config/` `usage/` | 索引/配置/计费 | 直接复用 |

R1（核心逻辑 Rust）在"axum 后端"方案下天然满足；不需要 WASM。

## 二、方案与工作量分解

**推荐栈**：axum（HTTP + WebSocket）+ 前端 SPA（React/Vue 任一，或
htmx 极简版）+ Monaco 编辑器（做题编辑；TUOJ 课件页本身就带 Monaco，
样式可对齐）。会话模型按**单用户单会话**做（课程 demo 场景），不做多
租户——那是另一个量级的工程（鉴权/隔离/并发写 index）。

| 模块 | 内容 | 估计 |
|---|---|---|
| 后端骨架 | axum 服务、静态资源、会话生命周期（进程内单会话） | 0.5 天 |
| 对话流 | POST/WS 收发消息；`run_turn` 的 progress 闭包 → WS 事件（spinner 等价物）；Ctrl-C 打断 → abort 消息 | 1 天 |
| 流式渲染 | 回复以事件推送到前端，前端 MD 渲染（marked/markdown-it） | 0.5 天 |
| 出题/做题 API | practice 状态机改造：面板列表/选题/编译运行/评审门/复盘全部变为无状态端点（compile_and_run 等本就是函数调用，改造机械） | 1-1.5 天 |
| 编辑器 | Monaco 集成 + 保存后触发编译 | 0.5 天 |
| 画像/用量页 | /stats、/usage 数据已是 JSON，直出表格 | 0.5 天 |
| 前端整体 | 布局、状态管理、事件流 UI、样式打磨 | 2-4 天（决定成品观感的主要变量） |
| 联调测试 | 端到端 + 打断/超时/预算拦截等边界 | 1 天 |
| **合计** | MVP（对话+出题+做题）：**4-5 天**；完整版：**7-12 天** | |

## 三、主要技术风险

1. **阻塞模型**：REPL 是单线程阻塞循环；Web 下每个回合要扔进
   `spawn_blocking`（reqwest blocking 不能进 async 上下文）。改造点
   集中、机械，但打断语义（现在的 Ctrl-C 标志 + 线程放弃）要映射成
   "客户端断开/取消按钮 → 置打断标志"，可行。
2. **交互循环假设**：practice 的 `read_line` 循环深嵌在 `cli/` 里，
   Web 版不复用它，而是直接暴露状态机原语——需要一次"把练习交互从
   I/O 中解耦"的小重构（纯逻辑部分本就在 `exercise/`/`review/`，
   影响面可控）。
3. **长连接超时**：L3 自由生成可达数分钟，WS 需要心跳与前端"生成中"
   态的耐心设计（CLI 的 spinner 等价物）。
4. **安全**：题目代码用本地 rustc 编译执行——Web 化若暴露到公网等于
   提供任意代码执行。**必须**只在本地/校园网运行，或加沙箱（那是
   另一个工程）。这也是"暂不做 Web"的实质理由之一。

## 四、收益判断与建议

- 硬要求 R2 已由 CLI 完整满足；Web 的边际收益集中在**展示观感**
  （课堂 5 分钟演示里浏览器确实更"好看"）。
- 但 9.6-9.10 的剩余时间优先级应是：试用反馈修复 > 演示脚本熟练度 >
  模板批次三。Web UI 的 4-5 天 MVP 会挤占前两者，且引入新的演示风险
  （现场浏览器演示翻车概率高于终端）。
- **建议**：9.10 前不做；把本文档作为"课后延伸路线图"。若后续要做，
  先做"练习交互与 I/O 解耦"的重构（对 CLI 也无害），再上 axum。
