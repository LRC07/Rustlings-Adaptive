# 出题规划（M4.5：把"出题"这件事做好）

> 定位：M4.5 的实施规划。设计文档 v3 §7.5 已定分层出题骨架（三级漏斗 +
> 统一质量门），本文回答它的三个前提问题：**需要怎样的题（规格）→ 题目
> 怎么组织 → 题目怎么生产与筛选**，并给出 a/b/c/d 落地顺序。
>
> 分工：本文 = 出题域的实施规格；设计文档 v3 §7.4 引用本文 §2 的七条
> 约束、§8 的 M4.5 拆分为四步指向本文 §5。
>
> 判断标准只有一条：**从其它语言过来的 Rust 初学者用起来是否实用**。
> 每条设计都能回答"这为用户解决了什么"。

## 0. 现状与问题

| 方面 | 现状 | 问题 |
|---|---|---|
| 组织 | `exercises/generated/` 平铺、`_2/_3` 后缀；`.progress` 只记做过/没做过；8 道种子 fixture 混在 `/practice` 全库列表 | 题目无语义身份（概念/来源/触发原因/状态）；对话语境与做题流断开；产量上来后不可导航 |
| 质量 | 12 模板 = 12 骨架 × 2–3 个词槽 | 填槽只能换词，题目结构、场景、考察角度被模板锁死；几乎全是"应用型"题（照着改），没有"决策型"题（多种修法都能编译，约束逼你选惯用解）；难度标签有、阶梯无——M5 复盘要出"变式/升难度"时将无弹药 |
| 范围 | 三层漏斗第 1 级覆盖率 = 12 模板的边界；第 1/3/5 讲是洼地（见模板主题规划） | 第 2/3 级（改编/自由生成）只有管线骨架，**缺一份"好题规格"约束 LLM 产出**——质量门只保证"能编译、能判分"，不保证"值得做" |

## 1. 用户旅程倒推：题目四象

| 象限 | 从哪来 | 要求 |
|---|---|---|
| **变式性** | 解释报错后巩固——做一模一样的题是复读，同根因换场景才是检验迁移 | 同根因 × 多**结构位置**（函数参数处 / 循环体内 / 结构体字段 / 闭包捕获 / 迭代器链 / 方法接收者） |
| **阶梯性** | "把所有权练一遍"要循序渐进 | 同概念至少 easy/medium 两档（hard 视进度） |
| **决策性** | "我懂了"要验证，就得让用户**选修法**而非套修法 | 题面预留"能编译但差"的退路（clone 逃逸、unwrap），用约束与测试逼出惯用解 |
| **覆盖性** | 课程对齐 + 高频错误码 | P0 概念全覆盖，洼地优先（迭代器 / Option / 错误传播 / 闭包 / Rc·RefCell） |

## 2. 题目规格：七条逻辑约束

> 这是题目生成（手写与 LLM 共用）的 rubric，也是人工筛选的 checklist。
> 机器可判的条目标 ✅（纳入质量门）；其余人工判定。

- **C1 一题一根因**：失败必须归约到单一 root cause（落 `review_hints.root_cause[0]`）。需要两个"啊哈"才能修好的题 → 拆成两道。
  ✅ 可检部分（M4.5b 已落地，`template::first_error_matches`）：未完成模板**编译失败**时，首个 error 级诊断码必须 ∈ 模板声明的 `error_codes`（防"声称考 E0382 实际报 E0308"）；`todo!()` 型模板（编译通过、测试失败）无编译错误，检查自动跳过。落地时修正了 3 个模板的声明不一致（generic-struct-swap +E0599、own-move-basics +E0308、trait-bounds +E0599）——首错误码检查从第一天就抓到了真问题。
- **C2 场景真实**：题面做一件可用人话描述的小事，5 秒看懂"这段代码想干什么"；禁止纯抽象签名练习。题面注释第一段 = 场景描述。
- **C3 坑来自真实混淆**：模板新增 `confusion` 字段，标注"从哪门语言的什么直觉会掉进来"（如：Java/Python 赋值是引用语义 → 以为 `let b = a` 后 `a` 仍可用）。写不出 confusion 的题，多半不值得存在。
- **C4 修法分高下**：题面预留"能编译但差"的退路，靠约束（no-clone / iterators-only…）与测试逼出惯用解——这是 M5 复盘对比表的素材来源。模板新增 `anti_patterns` 声明预期差解（如 `clone-everywhere`、`unwrap-ladder`），供评审门比对。
- **C5 难度 = 决策点数**，不是行数：
  - easy：认出问题 + 套用唯一修法（加 `&`、加 `mut`、加 `move`）
  - medium：在 2–3 种合理修法里**选**一个（借用 vs clone vs 重建），或错误不直观（NLL、部分移动）
  - hard：结构重组（拆字段借用、加生命周期标注、改迭代器链、用 entry）
  同概念至少两档；`difficulty` 字段必须能按此定义说清"决策点是什么"。
- **C6 变体换场景不换皮**：同根因变体必须改变结构位置或任务形态，不许只换变量名。槽位是"换词"，变体是"换结构"——扩容时以后者为主。
- **C7 机器可校验最大化**：测试直连可观察行为、期望值由槽位计算（已有纪律）；凡 rustc / 测试 / 约束能判的（编译、通过性、约束、首错误码、行数）一律不进 LLM 主观判断；LLM 只负责场景编写与根因解释。

## 3. 题目组织

### 3.1 数据层：index.json 是单一事实来源

新增 `exercises/generated/index.json`，存所有**非 fixture** 题目的元数据与状态；文件系统只管存储，界面从索引渲染。

```rust
struct ExerciseMeta {
    path: String,              // "generated/own_move_basics.rs"，相对 exercises/，作 key
    title: String,
    concepts: Vec<String>,     // 图谱 id
    error_codes: Vec<String>,
    difficulty: Difficulty,
    source: Source,            // TemplateFill{template_id, slots} | Adapted{base} | Free | Unknown
    session_id: Option<String>,// 哪个会话产出
    trigger: Option<String>,   // 一句话触发语境（"你贴的代码报 E0382"）
    created_at: String,
    attempts: u32,
    status: Status,            // Pending | Failed{times} | Passed | Skipped
    feedback: Option<Feedback>,// TooEasy | JustRight | TooHard | Pointless
}
```

- **状态收敛**：做题状态（含完成标记）统一写 index.json；`.progress` 首次运行迁移后退役（读一次合并进 index，之后不再写）。
- **对账**：启动时扫 `exercises/` 与 index 比对——缺条目补录（`source=Unknown`，从文件头注释恢复 title/concepts）；孤儿条目标 missing 不删。
- **会话与题目解耦**：`Session.exercises` 只存该会话产出的 path 列表（顺序即产生顺序），呈现时 join index——避免双份元数据不一致，跨会话也能按 session_id 查。

### 3.2 界面层：`/practice` 三层分区（编号全局连续）

```
── 做题模式 ──   进度 [████░░] 5/12
  本会话（3）                      ← 对话产出优先、按产生顺序，带 ✓/✗ 状态
    1. [ ] 所有权移动：函数拿走所有权后原值不可再用   E0382 · easy
    2. [✗] 部分移动：取走字段后整个值不可再用        E0382 · medium
  按主题                           ← 从 index 按 concepts 聚合（叶子归并到一级域显示）
    所有权(6)  借用(4)  错误处理(3) …            [t] 展开
  全库                             ← 现有列表（fixture 已过滤）   [a]
  <数字> 选题   n 下一题   v 验证   f 反馈   b 返回
```

- 单题卡片（进入做题时）：标题 + 概念 / 难度 / 来源 / 触发语境一行；失败时 rustc 首错误码高亮。
- **`f` 反馈**：太简单 / 合适 / 太难 / 没意义 → 写 index.feedback。这是质量门第 4 层（§7.4）的数据起点，不强制、不打扰。

### 3.3 种子题 fixture 化（提前自 M8，设计文档 §8 已定稿）

8 道种子题移入 `exercises/fixtures/`；`discover` 默认过滤；`/practice` 的"全库"分区不显示（`/practice all` 显式查看）；IDE 子 crate 接线同步移动。解决"界面混乱"。

### 3.4 对话耦合（先于 M5 的轻量闭环）

1. **出题卡片**：对话中生成成功后渲染题卡（标题 + 概念/难度/来源 + **为什么出这题**的一行触发语境），回车进入做题——回答"这题为什么给我"。
2. **`[a] 问教练`**：做题页新命令，把当前代码 + 最近一次诊断组装成用户消息带回对话（M5 评审门的自然入口，一次接线两用）。
3. **状态回流**：做题结果写 index（含 session_id），Agent 回合的 system prompt 注入"本会话题目状态摘要"——教练知道你练到哪了，为 §4.4 主动出题形态打底。
4. **触发语境记录**：Agent 工具 `generate_exercise` 增加可选 `reason` 参数（教练用一句话说明为何出题），落 trigger 字段。

## 4. 生产与筛选

关键认识：**模板不是唯一资产，规格卡才是**——同一份规格卡既驱动手写模板，也作为第 2/3 级生成的 prompt rubric；且 M5 的 follow-up（变式/升难度）依赖 §2 的难度阶梯先存在。

### 4.1 规格卡（每个 P0 概念一张）

```
- concept_id          图谱叶子 1–2 个（缺节点先扩 taxonomy 再出题）
- error_codes         首诊断码必须命中的集合（纯逻辑题豁免需说明）
- root_cause          一句话"啊哈"
- confusion           源语言直觉 → 掉坑路径（C3）
- 场景库              2–3 个真实小任务候选，各标注结构位置（C6 的轴）
- 修法谱系            惯用解 / 差解（能编译）/ 更优解（C4）
- 难度定义            本题 easy/medium/hard 各自的决策点（C5）
- 测试要求            断言哪些可观察行为；期望值如何由槽位计算（C7）
- 槽位与变体轴        换什么（词）、变什么（结构）
```

### 4.2 批量产稿流程（已确认：LLM 产稿 + 人工筛选）

```
P0 概念 → 规格卡（可先半自动：从课件 §x.y 小节 + 高频错误码 + 现有模板提炼，人工过目）
  → LLM 按规格卡批量产候选（每卡 3–5 个，prompt = 规格卡 + 七条约束 + 1–2 个已验证模板作 few-shot）
  → 自动层筛选（机器，全量）：三重校验 / 规则过滤 / 约束自洽 / 首错误码匹配（C1✅）
  → 人工 checklist（七条约束逐条 + "做完能说出啊哈吗"）→ 每卡留 1–2 个
  → 落库 templates/*.toml（schema v2：补 confusion / anti_patterns），fixture 测试兜底
    （src/template/mod.rs 的 repo_template_library_is_consistent_and_valid 自动扩断言，红了修模板不改测试）
```

### 4.3 实测层（持续）

- 抽样试做：自己 + 2–3 位同学各做若干，记录卡点与用时；反馈 `f` 数据落 index。
- 阈值规则（§7.4 第 4 层）："太难/没意义"占比高 → 降推荐优先级或回炉。

### 4.4 分工与规模预期

- **手写/产稿落库**：批次一 12 主题（模板主题规划.md 的表仍有效）× 1–2 档 ≈ 20–30 个模板；批次二按余量。老 12 模板按 schema v2 补字段并复核难度定义。
- **生成管线**（M4.5c）：变体长尾交给第 2/3 级，prompt 以规格卡 + 七条约束 + few-shot 模板为 rubric；手写库覆盖第 1 级命中率与离线兜底。
- 总盘子 40–60 个模板，不追求量，每张规格卡宁缺毋滥。

## 5. 落地切分

| 步骤 | 内容 | 验收 | 依赖 |
|---|---|---|---|
| **M4.5a 题目组织**（≈1 session，先行） | §3 全部：index.json + 三层界面 + fixture 化 + 对话耦合四件套 | 对话出题 → 题卡 → 做题 → `[a] 问教练` / 状态回流闭环可演示；列表无 fixture 杂音；`.progress` 迁移 | 无 |
| **M4.5b 规格 + 质量门升级**（半天） | 七条约束已在本文（§2）；质量门实现 C1✅ 首错误码匹配；模板 schema v2 字段 + 老 12 模板补齐 | fixture 测试含首错误码断言；老模板过新检查 | 无（可与 a 并行） |
| **M4.5c 分层出题**（1–1.5 session） | 设计文档 §7.5：ExerciseDraft 统一表示 + 第 2 级改编 + 第 3 级自由生成 + 修复环；**前置硬化**（verifier 超时、ban 约束、概念 miss log）先行 | "给一道 Box<dyn Error> 传播的题"（无直配模板时）产出可开练的题；三层各有演示路径；prompt 含规格卡 rubric | b |
