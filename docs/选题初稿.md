选题：RustLings-Adaptive —— 自适应 Rust 学习 Agent
==================================================

【项目背景】

本课程的核心任务是“在 AI 辅助下用 Rust 完成一个大作业”，本质上是一个
“边学 Rust、边造物”的过程。而 Rust 的学习曲线在主流语言里偏陡：所有权
与借用、生命周期、泛型、trait 与 trait object、错误处理等概念，仅靠文档
很难内化。社区公认上手最快的方式是 rustlings 这一类“填空式”小练习——
给一段故意写残的代码让学习者补全，由编译器和测试当场判对错，反馈是机器
级的、即时的，远比读教程有效。

但原始 rustlings 有三个明显短板：
  1. 题目固定：所有人做同一套，不区分基础与短板；
  2. 难度一档：无分级，也不会因某类错多而加练；
  3. 无个性化反馈：只知“过/没过”，不知为何错、错在哪、下次补什么。

【选题原因】

我自己在用 rustlings 走泛型与 trait 两章时就发现：哪怕做完一遍，遇到稍有
变化的场景仍在同一类错误上栽——例如“把 bound 写在 impl 上而非方法上”
“忘给 trait object 加 Send”。rustlings 不记我错在哪，更不会据此出变体。

直接问通用 LLM 出题也不可行：它不保证代码能编译，常给有语法/类型错的
“练习”；不了解我的历史错误，出题泛泛；更不会在本地用 rustc 实际验证题目
可解。根本原因在于通用 Agent 既缺持久状态，也无法可靠地在本地执行与校验。

痛点由此成型：需要一个“懂 Rust 编译器反馈、又懂个人错误画像”的学习
Agent，把出题、验证、复盘、诊断、再出题串成一个闭环。这也契合“即用即学”
的 AI 辅助学习范式。

【项目简介】

RustLings-Adaptive 不是一个“出题器”，而是一个分层 Rust 学习 Agent，
rustlings 式填空只是其入口之一。整体分三层：

  - 验证引擎层（Rust）：把 rustc / cargo / clippy / proptest 作为 Agent
    可调用工具，提供真实可执行、可校验的底层能力。
  - 状态层：概念图谱（每节点带 SM-2 掌握度）+ 错题本（带检索）+ 会话历史。
  - Agent 环：生成 → 本地三重校验 → 做题 → 解释评分 → 诊断最小化 →
    归档 → 按掌握度定向再生成。

核心闭环：依据薄弱知识点生成填空题（含 todo、测试、参考解）→ 本地
rustc --test 做“能编译 / 参考解全绿 / todo 模板必失败”三重校验，不过则
自动重生成 → 学习者在交互式 CLI 做题，实时编译测试反馈 → 采集编译错误
与 panic，归入错误画像与错题本 → 据此定向再出题，专攻薄弱点。

【与通用 Agent 相比的亮点（场景定制化）】

1. 本地编译器即工具（Tool Use）
   把 rustc --test 包成 Agent 工具，每道候选题必须通过本地三重校验才入库。
   通用 LLM 出题常给不能编译或带逻辑错的代码；本 Agent 保证题目机器可解、
   质量可控。这是通用 Agent 做不到、也最基础的定制点。

2. 借用检查器假设实验室（招牌功能）
   学习者假设性地修改代码（如增加生命周期参数、改 ref），Agent 实际重跑
   rustc 并返回诊断增量（旧错误码 → 新错误码），让借用规则的因果可观察。
   通用 Agent 解释借用错误只能从报错文本猜，常一本正经地胡说；本 Agent
   以真实编译器为据。这是所有语言中 Rust 独有、最可辩护的差异化点。

3. 可验证解释评分
   学习者用自然语言解释为何修复有效，Agent 不只评语言，还生成若干“探针
   变体”实际编译运行，检验其解释能否预测这些变体的成败——能预测即真懂，
   否则只是背答案。把“是否理解”机器化衡量，离不开真实 rustc。

4. 错误画像驱动的自适应与错题本
   从历次编译错误码与 panic 聚类（如 E0277 高发 → 多出 trait 实现题），
   形成个人能力图谱；每条错误归档（诊断、最小复现、修复、概念标签、解释、
   评判），下次出错时检索相似旧错。通用 LLM 一次性出题、无记忆、无定向。

5. 结构化输出与工程接驳
   用 JSON Schema 约束输出（知识点/难度/todo/测试/参考解），校验失败自动
   重试；通过的题写入 exercises/ 并自动接线，生成完即可在 rust-analyzer
   全功能下练习。通用 LLM 给的只是散装代码。

【主要功能】

- 交互式 CLI：选题、做题、实时编译/测试反馈、进度渲染、长任务可打断。
- 模型可配置：endpoint / key / 价格 / 上下文长度 / 思考模式，支持 OpenAI
  与本地模型自由切换（配置文件或 CLI 设置页）。
- 题目生成与本地三重校验：知识点 + 难度输入 → LLM 生成 → rustc 验证 →
  入库并自动接线。
- 复盘与评分：多解经验比较（clippy/编译时/运行时）、可验证解释评分、
  诊断最小化。
- 错误画像与错题本：采集错误、聚类成能力图谱、带检索归档、定向再生成。
- 历史与轨迹可回看：每次会话存 JSON，展示 Agent 实际工作流程，非黑盒。
- Token 用量与价格统计：每次调用记 input/output token，按配置价格换算，
  支持预算上限自动中断。

【MVP 取舍】

为避免范围失控，主线只锁三个环且互成闭环：① 生成 + 三重校验（骨架已
就绪）；② 可验证解释评分（复盘核心，差异化最硬）；③ 错题本 + 检索（沉淀
评分结果，吃 R5）。借用检查器假设实验室作为明星功能单列，用于展示。其余
方向（proptest 边界发现、项目感知练习、诊断→练习合成、多语言迁移）列入
设计前瞻，主线不碰。

【一句话总结】

把 rustlings 的“机器级即时反馈”与 LLM 的“按需生成”结合，以真实 rustc
为验证引擎、以错误画像与错题本为状态层，做一个“练—评—记”自适应闭环、
通用 Agent 做不到的 Rust 学习 Agent。

【设计前瞻】

- 验证器与语言解耦：rustc 换成 gcc / tsc / go test，框架可迁移到 C /
  TypeScript / Go 的自适应练习。
- 项目感知：扫学习者真实 Cargo 项目与 clippy 警告，生成“项目正需要的
  概念”的题，接地真实仓库。
- 诊断→练习合成：从学习者自有项目的一条报错，合成能复现同一 E0xxx 的
  最小练习。
