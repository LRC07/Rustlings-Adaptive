# Rustlings-Adaptive 设计文档（v1 初版）

> 状态：初版，未决项以「（留白）」或 TODO 标注，随实现迭代对齐。

## 1. 产品定位

**一句话**：一个自适应 Rust 学习 Agent，以 rustlings 式填空练习为入口，把
"生成 → 本地验证 → 做题 → 复盘评分 → 归档 → 定向再生成"串成闭环。

- **给谁用**：正在学 Rust 的开发者（含本课程同学），尤其是卡在所有权/借用、
  生命周期、泛型、trait 等编译期概念上、读完文档仍不会写的人。
- **解决什么问题**：rustlings 题目固定、不区分短板、无个性化反馈；通用 LLM
  出题不保证可编译、不了解学习者历史错误、不本地验证。两者都形不成"做错→
  诊断→针对性再练"的闭环。

## 2. 目标用户与痛点

| 痛点 | 现状 | 通用 Agent 为什么解决不好 |
|---|---|---|
| 同一类错反复犯 | rustlings 不记录错误，做完一遍仍原地栽 | 无持久状态，跨会话不记忆 |
| 题不针对短板 | 所有人做同一套 | 不了解学习者历史，出题泛泛 |
| LLM 出的题常不可编译 | 直接问 ChatGPT 给的代码常带语法/类型错 | 不会本地跑 rustc 验证 |
| 借用错误看不懂 | 报错冗长，模型从文本猜常一本正经胡说 | 缺真实编译器，无法还原因果 |
| "懂了"无法衡量 | 只能凭感觉 | 无可执行探针检验理解 |

根本原因：通用 Agent **既缺持久状态，也无法可靠地在本地执行与校验代码**。
本项目的全部差异化都建立在这两点之上。

## 3. 场景定制（通用 Agent 做不到的事）

下列每项都以"真实本地执行 + 可验证"为前提，共 5 点（≥2 项硬性要求已覆盖）：

1. **本地编译器即工具（Tool Use）**：把 `rustc --test` 包成 Agent 可调用工具，
   每道候选题必须通过三重校验（能编译 / 参考解全绿 / todo 模板必失败）才入库。
2. **借用检查器假设实验室（招牌）**：学习者假设性改代码（加生命周期、改 ref），
   Agent 实际重跑 rustc 返回**诊断增量**（旧错误码→新错误码），让借用规则因果可观察。
   Rust 独有、最可辩护的差异化点。
3. **可验证解释评分**：学习者用自然语言解释"为何修复有效"，Agent 生成若干探针
   变体实际编译运行，检验解释能否预测变体成败——把"是否真懂"机器化衡量。
4. **错误画像驱动的自适应 + 错题本（带检索）**：聚类历次错误码/panic 形成概念
   图谱，定向再出题；每条错误归档，下次出错检索相似旧错。
5. **结构化输出与工程接驳**：JSON Schema 约束 LLM 输出，校验失败自动重试；
   通过的题写入 `exercises/` 并自动接 `lib.rs`，生成完即可在 rust-analyzer 下练。

## 4. 核心交互流程

界面：交互式 CLI（满足 R2）。命令模式 + 子菜单。

### 4.1 练习生成（generate）
```
输入：知识点(如 "trait object") + 难度(easy/medium/hard)
  → [进度] 生成候选 #1 … 验证 1/3 … 重生成 … 验证 3/3 ✓
输出：新练习已入库，列出题目/考点；可选立即开练
```
长任务（>3s）显示 "验证 N/M"，可 Ctrl-C 打断（R4）。

### 4.2 做题（practice）
```
输入：选题号 → $EDITOR 打开 → 补全 TODO → [r] 运行
输出：rustc --test 实时结果（编译错误/测试通过数）；失败可改后重跑
通过后 → 进入"解释评分"子流程
```

### 4.3 解释评分（review，通过后触发）
```
输入：学习者用自然语言写"为什么这样改就对了"
输出：Agent 生成 3-5 个探针变体 → 实际编译运行 → 评分（预测命中率）+ 简评
      → 归入错题本/概念图谱
```

### 4.4 借用实验室（borrowlab）
```
输入：贴一段代码（或选当前题片段）+ 假设性改动（"加 'a 生命周期"）
输出：rustc 诊断增量（diff 形式：旧 E0xxx → 新 E0xxx）+ Agent 解读
```

### 4.5 统计（stats）
```
输出：概念掌握度图谱（SM-2 曲线）、错题本列表（可检索）、token 用量与花费
```

## 6. 数据源

| 数据 | 来源 | 用途 |
|---|---|---|
| 编译诊断（结构化） | `rustc --error-format=json` / `--json` | 验证、画像、诊断增量 |
| clippy 诊断 | `cargo clippy --message-format=json` | 多解比较（P2） |
| LLM 能力 | OpenAI 兼容 API（可配本地） | 生成、评分、解读 |
| 种子练习 | 现有 `exercises/` 8 道 | 冷启动、格式参照 |
| 错误码索引 | rustc 仓库 `rustdoc error index`（可选抓取） | 诊断→概念映射 |
| 概念分类法 | 手工：概念↔错误码表（如 E0277↔trait impl） | 画像与定向出题 |
| 用量与价格 | API 响应 usage 字段 + 配置价格表 | R6 统计 |

> 概念分类法与错误码映射初期手工维护，后续可据做题数据反哺修正。

## 7. 技术设计

### 7.1 模块划分

```
rustlings-adaptive/                     (bin: CLI 入口，已存在)
├── src/
│   ├── main.rs                   CLI 菜单与子命令调度（已存在，扩展）
│   ├── cli/                      交互、进度渲染、打断
│   ├── config/                   模型配置加载（.env / config.toml）— R3
│   ├── llm/                      LLM 客户端（reqwest + tokio）、调用编排 — R1
│   ├── exercise/                 练习数据模型、发现、rustc 运行器（已部分存在）
│   ├── verifier/                 三重校验、诊断解析（rustc --json）
│   ├── generator/                生成 + JSON Schema 校验 + 重试 + 自动接线
│   ├── reviewer/                 可验证解释评分（探针变体）— P0
│   ├── borrowlab/                借用假设实验室（诊断 diff）— P1
│   ├── profile/                  概念图谱(SM-2)、错误画像、错题本+检索 — P0
│   ├── store/                    持久化（JSON 落盘；后期可换 sqlite）
│   ├── usage/                    token/价格统计、预算中断 — R6
│   └── agent/                    Agent 环：工具定义、调度、轨迹记录 — R5
├── exercises/                    练习仓 + IDE 子 crate（已存在）
└── tests/                        集成测试
```

### 7.2 关键数据结构

```rust
// 练习
struct Exercise {
    id: String,            // 路径派生
    path: PathBuf,
    name: String,
    category: String,
    title: String,
    concept_tags: Vec<String>,   // 如 ["trait_object","dyn"]
    difficulty: Difficulty,
    source: ExerciseSource,      // Seed | Generated(GenerationMeta)
}

// LLM 生成输出（JSON Schema 约束）
struct GeneratedExercise {
    title: String,
    statement: String,            // 题面
    knowledge_points: Vec<String>,
    difficulty: Difficulty,
    template_code: String,       // 含 // TODO 与 // I AM NOT DONE
    tests: Vec<TestCase>,
    reference_solution: String,
}

// 三重校验报告
struct VerifyReport {
    compiles: bool,
    ref_solution_passes: bool,
    template_fails: bool,         // todo!() 模板下测试必须失败
    diagnostics: Vec<Diagnostic>,
}

// 诊断（从 rustc --json 解析）
struct Diagnostic {
    code: Option<String>,         // "E0277"
    message: String,
    severity: Severity,           // error/warning
    spans: Vec<Span>,
}

// 一次做题记录
struct Attempt {
    exercise_id: String,
    ts: DateTime,
    user_code: String,
    verify_report: VerifyReport,
    errors: Vec<Diagnostic>,
    duration_ms: u64,
}

// 概念节点（SM-2 间隔重复）
struct ConceptNode {
    id: String,                   // "trait_object"
    name: String,
    mastery: f32,                 // 0..1
    ease: f32,                    // SM-2 ease factor
    interval_days: u32,
    last_review: Option<DateTime>,
}

// 错题本条目
struct NotebookEntry {
    id: String,
    exercise_id: String,
    diagnostic: Diagnostic,
    minimal_repro: Option<String>, // P2 诊断最小化产物
    fix: String,
    concept_tags: Vec<String>,
    user_explanation: Option<String>,
    llm_judgment: Option<ExplanationJudgment>,
    related_exercises: Vec<String>,
    ts: DateTime,
}

// 解释评分结果
struct ExplanationJudgment {
    score: f32,                    // 探针预测命中率 0..1
    probes: Vec<ProbeResult>,      // 每个探针变体的实际成败 + 学习者预测
    comment: String,
}

// 模型配置 — R3
struct ModelConfig {
    endpoint: String,
    api_key: SecretString,
    model: String,
    context_len: u32,
    think_mode: bool,
    prices: Prices,                // input/output per 1M tokens
    budget: Option<Budget>,        // 预算上限
}

// 用量记录 — R6
struct UsageRecord {
    ts: DateTime,
    model: String,
    input_tokens: u64,
    output_tokens: u64,
    cost: f64,
    phase: Phase,                  // 生成/评分/解读/…
}
```

### 7.3 关键流程数据流（生成→验证→入库）

```
[知识点+难度] → generator → LLM(JSON) → schema 校验
   ↓ (失败重试)
verifier: rustc --test (template)  必须 fail
verifier: rustc --test (ref-sol)   必须 pass
   ↓ (三重通过)
store: 写入 exercises/<cat>/<name>.rs
wire:  追加 #[cfg(rust_analyzer)] mod 到 exercises/lib.rs
usage: 记录本次调用 token/价格
```

### 7.4 工具表（Agent 可调用）

| 工具 | 输入 | 输出 |
|---|---|---|
| `verify_code(code, mode)` | 代码 + 模板/参考 | VerifyReport |
| `run_tests(file)` | 练习文件 | 测试结果 |
| `minimize_diagnostic(code)` | 失败代码 | 最小复现（P2） |
| `apply_edit_and_check(code, edit)` | 代码 + 改动 | 诊断 diff（借用实验室） |
| `query_notebook(concept)` | 概念 | 相似旧错条目 |
| `record_attempt(attempt)` | Attempt | 更新图谱/错题本 |
