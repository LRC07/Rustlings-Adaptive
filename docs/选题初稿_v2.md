选题：RustLings-Adaptive —— 对话式 Rust 诊断教练
====================================================

【项目背景】

本课程的核心任务是“在 AI 辅助下用 Rust 完成一个大作业”，本质上是一个
“边学 Rust、边造物”的过程。而 Rust 的学习曲线在主流语言里偏陡：所有权
与借用、生命周期、泛型、trait 与 trait object、错误处理等概念，仅靠文档
很难内化。社区公认上手最快的方式是 rustlings 这一类“填空式”小练习——
给一段故意写残的代码让学习者补全，由编译器和测试当场判对错，反馈是机器
级的、即时的，远比读教程有效。

但 rustlings 题目固定、不区分短板、也不记录学习者的错误。另一方面，通用
LLM 能把概念解释清楚，却不会在本地跑 rustc 验证它给的代码，也不记学习者
错在哪。结果是：解释完用户说“我懂了”，实际遇到稍有变化的场景还是错；同
一类错误反复犯，没人定向巩固。

【选题原因】

我自己在学泛型与 trait 时就反复经历这个循环：问 LLM 解释“为什么 bound
要写在方法上”，听完点头，下一题照样把 bound 写到 impl 上。rustlings 不
知道我错在哪，通用 LLM 知道怎么解释却不会验证我是否真懂，更不会在对话
里顺手出一道针对我刚暴露的薄弱点的题。

痛点由此成型：需要一个“懂 Rust 编译器反馈、又懂我个人错误画像”的对话
教练——不只是答疑，而是在对话中即时诊断并验证。

【项目简介】

RustLings-Adaptive 是一个对话式 Rust 诊断教练 Agent。rustlings 式填空
不再是独立题库，而是“对话中的即时诊断工具”：题目质量标准从“客观优秀”
降为“与当前上下文相关、能暴露薄弱点、机器可解”，绕开了稀疏数据下题目
质量难以量化的难题。核心闭环：

  1. 诊断：用户提问或贴报错 → Agent 解释，并解析其中的 rustc 错误码
     （E0xxx）作为知识点锚点。
  2. 出题：据薄弱知识点选/填一道填空题（模板化 + 参数化，见下），本地
     rustc --test 做“能编译 / 参考解全绿 / todo 模板必失败”三重校验，
     不通过自动重试。
  3. 做题：学习者在 CLI 中补全，实时编译测试反馈。
  4. 复盘：通过后做“原理解释 + 多解对比”复盘（见亮点 3）。
  5. 归档：错误码、修复、解释归入错误画像与错题本，据此定向巩固。

【与通用 Agent 相比的亮点（场景定制化）】

1. 本地编译器即工具 + 三重校验
   把 rustc --test 包成 Agent 可调用工具，任何要给用户的题必过本地三重
   校验。通用 LLM 给的代码常带语法/类型错；本 Agent 保证机器可解。

2. 错误码锚定的诊断与出题
   从用户编译错误解析 E0xxx（如 E0277↔trait-impl、E0499↔exclusive-
   mutable-borrow、E0382↔ownership-move），作为知识点锚点。错误画像
   精确到错误码级，出题与检索都据此定向。Rust 专属、结构化。

3. 原理解释 + 多解对比复盘
   通过后，Agent 复现原失败代码与真实 rustc 诊断，请学习者解释为什么会
   编译失败（原理层），并据真实错误码校核其解释是否切中要害；再生成
   2–3 种都能通过编译的不同写法（惯用/啰嗦/取巧），实跑 clippy 警告数、
   编译时长与运行时给出对比表，让学习者判断哪种更合适并说明理由，Agent
   据实测数据点评。把“是否真懂”建立在真实诊断与可测量的取舍之上，而非
   主观判断——这也比“预测能不能编译”在 rust-analyzer 实时反馈的时代
   更有意义。

4. 借用检查器假设实验室（招牌）
   学习者假设性改代码（加生命周期、改 ref），Agent 实际重跑 rustc 返回
   诊断增量（旧错误码 → 新错误码），让借用规则因果可观察。通用 Agent
   解释借用错误只能从报错文本猜，常一本正经地胡说；本 Agent 以真实编译
   器为据。

5. 错题本 + 检索闭环
   每条错误归档（错误码、最小复现、修复、解释、评判），下次同码出错检索
   相似旧错。持久状态 + 检索，通用 Agent 无状态。

【主要功能】

- 对话 REPL + 菜单：自然语言提问/贴代码，Agent 解释并即时出题；长任务
  进度渲染、可打断。
- 模型可配置：endpoint / key / 价格 / 上下文长度 / 思考模式，支持
  OpenAI 与本地模型自由切换。
- 模板化题目生成：10–20 手写模板（所有权/借用/生命周期/trait/泛型），
  LLM 选模板 + 填槽 + 字面量替换，三重校验后自动入库接线。
- 原理解释与多解对比复盘：复现失败+真实诊断校核解释、生成多解并实跑
  clippy/编译时/运行时给对比，检验是否真懂。
- 错误码画像与错题本：错误码聚类成概念图谱（SM-2 间隔重复）、带检索
  归档、定向再出题。
- 历史与轨迹可回看：每次会话存 JSON，展示 Agent 实际工作流程，非黑盒。
- Token 用量与价格统计：每次调用记 input/output token，按配置价格换算，
  支持预算上限自动中断。

【MVP 取舍】

主线只做：模板库 + 三重校验 + 对话 REPL + 原理解释与多解对比复盘 +
错误码画像与错题本。借用检查器假设实验室作为明星功能单列用于展示。
质量评估用“多层布尔门 + 用户反馈”（硬校验 / 规则过滤 / 用户标记太难
太简单），不追求连续分数。其余方向（自由生成、LLM 试做判难度、诊断
最小化、proptest、项目感知、多语言迁移）列入设计前瞻，主线不碰。

【一句话总结】

把 rustlings 的“机器级即时反馈”与 LLM 的“对话解释”结合，以真实 rustc
为验证引擎、以错误码为知识点锚点、以错题本为状态层，做一个对话中即时
诊断与验证、通用 Agent 做不到的 Rust 教练。

【设计前瞻】

- 验证器与语言解耦：rustc 换成 gcc / tsc / go test，框架可迁移到 C /
  TypeScript / Go 的对话式诊断教练。
- 自由生成与 LLM 试做判难度：在模板化稳定后，作为生成多样性扩展加入。
- 项目感知：扫学习者真实 Cargo 项目，在对话中针对其代码的薄弱点出题。
