# 开发复盘与决策点（M6，9.5 凌晨）

> 接续 `复盘_M5.md`（其 §四 D1–D8 决策点仍待用户拍板）。

## 一、M6 做了什么

1. **`profile/` 数据层**（12 单测）：粗轨 = rustc 错误码计数；细轨 = 概念
   SM-2（经典公式，EF 钳位 [1.3, 2.5]）+ 信号计数（attempts/passes/fails/
   used_hints/explanation hit/miss）；错题本从 exercise index 蒸馏
   （不重复存储），支持概念/错误码/标题过滤。持久化合并设计初版的三个
   文件为单一 `~/.rustlings_adaptive/profile.json`（单一写入方）。
2. **信号接线**：practice 每次编译（单题 + 批量 v）→ `record_attempt`；
   复盘四步走完 → `record_debrief`（含 SM-2 更新，质量由 M5 信号映射）。
3. **呈现**：`/stats` 画像页（到期复习 / 概念弱项 / 高频错误码 / 错题本，
   `/stats wrong <过滤>`）；做题面板 ⏰ 到期复习行；同概念失败 ≥2 次 ⚠
   提示行；`/stats` 无 LLM、全部确定性输出（项目原则）。
4. **教练接入**：practice_note 注入（弱项/到期/错题本 top3）+
   **`learner_profile` 工具**（与 list_concepts 对称的只读画像查询）。

## 二、关键发现（架构结论）：元信息注入 → 工具化

- `learner_profile` 落地前，画像信号以 `[Profile] …` 段注入 system prompt
  （practice_note 同路）。实测 kimi-k3 **连续无视**（直接回答"我访问不到
  你的做题历史"）——与 M5 open-loop note（system 头部与消息尾部两种位置）
  的表现一致。
- 对比：`check_code` / `generate_exercise` 等工具教练始终用得很好。
- **结论：对"教练可查的状态"，工具化（function calling）依从性远高于
  prompt 注入**；prompt 注入保留给轻量上下文（练习状态摘要），查询类
  数据一律走工具。
- 工具化后实测：教练主动调用 → 准确引用薄弱概念（带中文名）、到期复习、
  错题本失败第一（含错误码与概念归因）→ 给出针对性巩固建议。✅
