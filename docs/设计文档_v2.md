# Rustlings-Adaptive 设计文档（v2）

> **（已有后续版本 → [设计文档_v3.md](./设计文档_v3.md)，v3 为当前设计基线）**
>
> 相对 v1 的变更：定位从"自动出题器"转为"对话中的诊断教练"；新增
> **rustc 错误码作为知识点锚点**；题目生成改为**模板化 + 参数化**；质量
> 评估从连续分数改为**多层布尔门 + 用户反馈闭环**；复盘环节为
> **原理解释 + 多解对比**（据真实诊断校核解释、实跑多解测量取舍，
> 重型探针变体降为 P2）。

## 1. 产品定位

一个**对话式 Rust 诊断教练** Agent。用户在 CLI 中用自然语言提问/贴代码，
Agent 解释、必要时**在对话中即时插入一道针对性填空题**作为验证；题目不强
求独立构成完整题库，只要求"与当前上下文相关、能暴露薄弱点、机器可解"。

- **给谁用**：正在学 Rust 的开发者（含本课程同学），卡在所有权/借用、
  生命周期、泛型、trait 等编译期概念上的人。
- **解决什么**：rustlings 固定无个性化；通用 LLM 能解释但不会本地验证、
  不记错误、无法在对话中即时出可练的题。本 Agent 把"解释→验证→诊断→
  归档→定向巩固"做进同一对话。

## 2. 目标用户与痛点

| 痛点 | 现状 | 通用 Agent 为何解决不好 |
|---|---|---|
| 同类错反复犯 | rustlings 不记错误 | 无持久状态 |
| 解释完不知是否真懂 | 用户"我懂了"不可信 | 无可执行验证手段 |
| LLM 给的题常不可编译 | 直接生成代码带错 | 不本地跑 rustc |
| 借用报错看不懂 | 模型从文本猜常错 | 无真实编译器还原因果 |
| 不知该练哪个点 | 无错误画像 | 不了解学习者历史 |

根本原因：通用 Agent **既缺持久状态，也无法可靠本地执行与校验代码**。

## 3. 场景定制（通用 Agent 做不到的事）

1. **rustc 即工具 + 三重校验**：任何要给用户的题（模板或生成）必过本地
   `rustc --test` 三重校验（能编译 / 参考解全绿 / todo 模板必失败）。
2. **错误码锚定的诊断与出题**：从用户编译错误解析 E0xxx，作为知识点锚点
   （E0277↔trait-impl、E0499↔exclusive-mutable-borrow、E0382↔ownership-move
   …），据此选模板/检索旧错/定向巩固。Rust 专属、结构化。
3. **原理解释 + 多解对比复盘**：通过后，Agent 复现原失败代码与真实
   rustc 诊断，请学习者解释"为什么编译失败"（原理层），并据真实错误码
   校核其解释是否切中要害；再生成 2–3 种都能通过编译的不同写法，实跑
   clippy 警告数 / 编译时长 / 运行时给出对比表，让学习者判断哪种更合适。
   把"是否真懂"建立在真实诊断与可测量的取舍之上，而非主观判断。
4. **借用检查器假设实验室（招牌）**：假设性改代码 → rustc → 诊断增量
   （旧 E0xxx → 新 E0xxx），让借用规则因果可观察。
5. **错题本 + 检索闭环**：每条错误归档（错误码、最小复现、修复、用户解释、
   评判）；下次同码出错检索相似旧错。持久状态 + 检索。

## 4. 核心交互流程

CLI 主体是一个**对话 REPL**（满足 R2），辅以菜单跳转。

### 4.1 对话诊断（主流程）
```
用户：贴一段报错代码 / 问概念（"为什么这里要 &mut self"）
  → Agent：解释 + 判定薄弱知识点(错误码/概念)
  → [若需巩固] Agent 调用工具生成/选一道填空题（三重校验后展示）
用户：在 $EDITOR 补全 → [r] 运行
  → Agent：rustc --test 实时结果；失败给错误码级反馈
通过后 → 触发"原理解释 + 多解对比"复盘或直接归档
```
长任务（LLM/编译 >3s）显示进度，Ctrl-C 打断（R4）。

### 4.2 原理解释 + 多解对比复盘
```
Agent 复现：原失败代码 + 真实 rustc 诊断（错误码）
用户：解释"为什么会编译失败"（原理层）
  → Agent：据真实错误码校核解释是否切中要害（命中错误码/根因关键词）
Agent 生成：2–3 种都能通过编译的不同写法（惯用/啰嗦/取巧）
  → 实跑：clippy 警告数、编译时长、运行时 → 对比表
用户：判断哪种更合适 + 理由
  → Agent：据实测数据点评，归档
```

### 4.3 自然触发出题的几种形态
- 用户报错 → 解释后问"要不要做道类似的题巩固"
- 用户连续两次同码错误 → 主动插入诊断题
- 用户说"我懂了" → 用一道题验证（不信主观判断）

### 4.4 借用实验室 / 统计
- borrowlab：贴代码 + 改动 → 诊断 diff + 解读
- stats：概念图谱（SM-2）、错题本、token/花费

## 6. 数据源

| 数据 | 来源 | 用途 |
|---|---|---|
| 编译诊断（结构化） | `rustc --error-format=json` | 验证、画像、诊断增量 |
| clippy 诊断 | `cargo clippy --message-format=json` | P2 多解比较 |
| LLM | OpenAI 兼容 API（含 function/tool calling） | 解释、选题填槽、解读 |
| 题目模板 | 手写于 `templates/`（YAML/TOML） | 生成基座 |
| 错误码→概念表 | 手工（E0277↔trait-impl 等） | 画像与定向 |
| 错误码索引 | rustc 仓库 error index（可选抓取） | 错误码释义 |
| 用量与价格 | API usage + 配置价格表 | R6 |

## 7. 技术设计

### 7.1 模块划分
```
src/
├── main.rs                CLI 入口（已存在，扩展为 REPL+菜单）
├── cli/                   对话 REPL、进度渲染、打断
├── config/                模型配置（.env/config.toml）— R3
├── llm/                   OpenAI 兼容客户端 + tool calling — R1
├── exercise/              练习模型、发现、rustc 运行器（已部分存在）
├── verifier/              三重校验、rustc --json 诊断解析
├── template/              模板库加载、槽位填充、规则过滤
├── generator/             模板选择 + LLM 填槽 + 校验重试 + 自动接线
├── review/                原理解释+多解对比复盘 — P0
├── borrowlab/             借用假设实验室（诊断 diff）— P1
├── profile/               错误码画像、概念图谱(SM-2)、错题本+检索 — R5
├── store/                 JSON 落盘
├── usage/                 token/价格统计、预算中断 — R6
└── agent/                 Agent 环：工具定义、调度、轨迹记录
exercises/                 练习仓 + IDE 子 crate（已存在）
templates/                 手写题目模板（YAML/TOML）
```

### 7.2 关键数据结构

```rust
// ===== 题目模板（手写基座）=====
struct Template {
    id: String,
    concept_tags: Vec<String>,     // ["exclusive-mutable-borrow"]
    error_codes: Vec<String>,      // ["E0499"] 此题做错时常触发的码
    difficulty: Difficulty,
    code: String,                  // 含 {{slot}} 占位
    slots: Vec<SlotSpec>,          // 槽位约束（类型名/字面量范围）
    tests: Vec<TestCase>,
    reference_solution: String,
    review_hints: Option<ReviewHints>,   // 可选：复盘用的根因关键词/对比写法种子
}

// ===== 复盘：原理解释 + 多解对比 =====
struct ReviewRound {
    failing_code: String,
    diagnostics: Vec<Diagnostic>,        // 原失败的真实诊断
    user_explanation: String,
    explanation_hit: ExplanationCheck,    // 是否切中真实错误码/根因
    alternatives: Vec<SolutionVariant>,  // 2–3 种都能通过编译的写法
    comparison: ComparisonTable,         // clippy/编译时/运行时实测
    user_choice: Option<usize>,          // 学习者选的"最合适"
    agent_comment: String,
}

struct ExplanationCheck {
    target_error_code: Option<String>,   // 真实错误码
    hit_code: bool,                      // 解释是否提及真实码/根因
    score: f32,
}

struct SolutionVariant {
    code: String,
    style: SolutionStyle,                // Idiomatic / Verbose / Clever
    verify: VerifyReport,               // 必须三重通过
    clippy_lints: u32,
    compile_ms: u64,
    runtime_ns: u64,
}

enum Judgment { Review(ReviewRound), FullProbes(/* P2 */) }

// ===== LLM 生成产物（填槽后）=====
struct GeneratedExercise {
    from_template: String,         // template id
    filled_code: String,           // 槽位填充后的模板
    knowledge_points: Vec<String>,
    difficulty: Difficulty,
    reference_solution: String,
}

// ===== 三重校验 =====
struct VerifyReport {
    compiles: bool,
    ref_solution_passes: bool,
    template_fails: bool,
    diagnostics: Vec<Diagnostic>,
}

struct Diagnostic {
    code: Option<String>,          // "E0277"
    message: String,
    severity: Severity,
    spans: Vec<Span>,
}

// ===== 错误码锚定的画像 =====
struct ErrorProfile {
    by_code: HashMap<String, u32>,      // E0277 -> 出现次数
    by_concept: HashMap<String, f32>,    // concept -> SM-2 掌握度
    last_updated: DateTime,
}

struct ConceptNode {                  // SM-2
    id: String,
    name: String,
    mastery: f32,
    ease: f32,
    interval_days: u32,
    last_review: Option<DateTime>,
}

// ===== 错题本 =====
struct NotebookEntry {
    id: String,
    ts: DateTime,
    error_code: Option<String>,
    concept_tags: Vec<String>,
    minimal_repro: Option<String>,
    fix: String,
    user_explanation: Option<String>,
    judgment: Option<Judgment>,
    related_template: Option<String>,
}

// ===== 模型配置 / 用量（同 v1）=====
struct ModelConfig { endpoint, api_key, model, context_len, think_mode, prices, budget }
struct UsageRecord { ts, model, input_tokens, output_tokens, cost, phase }
```

### 7.3 Agent 工具表
| 工具 | 输入 | 输出 |
|---|---|---|
| `verify_code(code, mode)` | 代码 + 模板/参考 | VerifyReport |
| `instantiate_template(template_id, slots)` | 模板+槽位 | GeneratedExercise |
| `pick_template_by_error(code)` | E0xxx | 候选模板列表 |
| `apply_edit_and_check(code, edit)` | 代码+改动 | 诊断 diff（借用实验室） |
| `query_notebook(error_code)` | E0xxx | 相似旧错 |
| `record_attempt / record_notebook` | 记录 | 更新画像 |
| `check_explanation(failing_code, user_text)` | 代码+解释 | ExplanationCheck（据真实错误码） |
| `measure_solutions(variants)` | 多解代码 | ComparisonTable（clippy/编译时/运行时） |

### 7.4 题目质量门（多层布尔，非分数）
1. 硬校验：三重通过（必过）
2. 规则过滤：单一知识点、行数 10–30、todo! 数 ≤2、测试直连知识点
3. 用户反馈：尝试次数/放弃/完成时间/标记"太简单/太难/没意义"
   → 阈值规则降推荐优先级或降档（如 >60% 标太简单→降优先级）

### 7.5 持久化
`~/.rustlings_adaptive/`：`sessions/*.json`、`error_profile.json`、
`notebook.json`、`usage.json`。（留白：后期改 sqlite）

## 8. Coding 路线

**M0 骨架（已完成）**：CLI + 8 种子练习 + r-a 子 crate + rustc --test 跑练习。

**M1 LLM 接入与计费（R1/R3/R6）**
- `llm/`：OpenAI 兼容客户端 + tool calling
- `config/`：.env/config.toml 加载
- `usage/`：token/价格统计、预算中断
- 验收：CLI 输入 prompt，返回回复 + 打印 token/花费

**M2 模板库 + 三重校验（练环，R1）**
- `templates/`：10–20 手写模板（YAML）
- `template/`：加载 + 简单规则过滤（行数/todo 数）
- `verifier/`：rustc --json 解析 + 三重校验
- 验收：选模板→填槽→三重校验→入库+自动接线

**M3 对话 REPL + 进度/打断（R2/R4）**
- `cli/`：对话 REPL，Agent 调用工具在对话中出题
- 进度渲染 + Ctrl-C 打断
- 验收：贴报错→解释→出题→做题→通过，含打断

**M4 原理解释 + 多解对比复盘（评环）**
- `review/`：复现失败+真实诊断→校核学习者解释；生成 2–3 多解→实跑
  clippy/编译时/运行时→对比表→学习者选+理由→归档
- 验收：一道题通过后完整复盘，含解释命中判定与多解对比表

**M5 错误码画像 + 错题本（记环，R5）**
- `profile/`：错误码聚类→概念图谱（SM-2）；`store/` 落盘
- 错题本 + 检索（先按错误码/概念，后加 embedding）
- `agent/`：会话轨迹存 JSON 可回看
- 验收：同码错两次→主动出同概念题；stats 看图谱与花费

**M6 借用检查器假设实验室（招牌，P1）**
- `borrowlab/`：apply_edit_and_check + 诊断 diff 呈现
- 验收：贴代码+改动，看 E0xxx 增量与解读

**M7 收尾**
- README（编译/配置/运行/演示用例）、集成测试、演示脚本、对齐文档
