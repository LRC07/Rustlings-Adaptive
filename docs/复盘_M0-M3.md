## 一、做对的决策

1. **质量门先于生成器（M2→M3 的顺序）**。三重校验先落地，使模板成为
   "被门检验的数据"：M3.1 加模板零逻辑改动；M4.5 分层出题（改编/自由
   生成）成了质量门的自然延伸而非重构。这是本项目最重要的架构复利。
2. **离线优先**。LLM 全部可选化（填槽回退默认值、LLM 失败静默降级）：
   测试不烧钱、CI 不依赖网络、演示不怕断网、未配 Key 也能用。
3. **数据即代码**。templates/taxonomy 进仓库 + 仓库级 fixture 测试
   （每个模板真实跑三重校验），数据回归被测试兜住——本次两处模板
   笔误（省略规则漏标、测试类型推断）都是 fixture 测试抓的。
4. **设计文档同步纪律**。每处实现偏差当场写回 §8 备注块（含口径：
   行数怎么数、todo! 怎么数），新 session 零上下文损失。
5. **隐私红线前置**。config.toml/.env/sessions 的边界在动工前写入
   AGENTS.md，全程未破。
6. **产物隔离（M3.2）**。生成的练习与接线（lib_generated.rs）全部
   gitignore，用户本地实验不污染版本库——这是踩过一次坑后补的架构。

## 二、踩过的坑（均已闭环）

| 坑 | 根因 | 对策/教训 |
|---|---|---|
| TOML `[[slots]]` 吞掉后续顶层键 | 表格头之后的键属于该表 | 数据格式上 `deny_unknown_fields`，让错误尽早爆炸 |
| assert_eq! 比较 `Box<dyn Error>` 两次编译失败 | `Result` 的 PartialEq 要求 E: PartialEq | 含动态错误类型的断言用 `is_ok_and`/match |
| 生成文件"未出现在练习列表" | `./` 前缀路径与 discover 路径不等 | 路径比较前 canonicalize |
| 注释里的 "todo!" 被计入宏数 | 字符串匹配未剥注释 | 计数前剥离行注释；口径写进文档 |
| 槽位变化导致测试期望错位 | 期望值硬编码字面量 | 期望值必须由槽位计算（`a+b`、`word.chars().count()`） |
| 用户产物混入 git add -A | 生成物无隔离 | generated/ 与接线文件 gitignore，架构性解决 |

## 三、对最终目标的自检

> 目标：**交互式 Rust 诊断教练——在答疑解惑的恰当时机插入简洁但有力
> 的练习，帮助学习语言特性、培养更好的程序设计习惯。**

- **弹药（出题）**：已备。质量门 + 12 模板 + 37 节点图谱，且 M4.5 将
  放开"任意主题"（三层漏斗）。
- **时机（何时出题）**：**尚未开始，这是下一个主战场**。"报错解释后
  追问要不要练一道""同概念连错两次主动插题""说'我懂了'用题验证"
  （§4.4）全部依赖 M4 的 Agent 工具环与 M6 的画像。M4 不是"多一个
  界面"，而是把已有能力串成"诊断→锚定→出题→做题"闭环的第一步。
- **简洁有力（题目质量）**："简洁"已被规则过滤门禁（10–40 行、概念
  ≤2）；"有力"（根因解释、更优解对比、习惯养成）在 M5 评审门与复盘，
  模板里的 review_hints 种子已备好入口。
- **培养设计习惯**：约束系统（no-clone/iterator-only）是目前唯一的
  "习惯"抓手，M5 复盘时要在对比表里让约束的收益可感知（行数/clippy）。
